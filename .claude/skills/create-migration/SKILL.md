Створи міграцію для: $ARGUMENTS

1. Подивись `ls server/migrations` і візьми наступний номер `NNN` (три цифри). Назва: `NNN_опис_snake_case.sql`.
2. Прочитай 2–3 останні міграції й `server/migrations/000_baseline_schema.sql`, щоб узгодити стиль і не дублювати наявне.
3. Ніколи не редагуй уже застосовані міграції — лише новий файл. Схема міняється тільки так.
4. Пиши ідемпотентно, де це можливо (`IF NOT EXISTS`, перевірка через `information_schema`), зважай на зовнішні ключі
   (міграція 004: RESTRICT для художників/користувачів, CASCADE для повідомлень комішену).
5. Якщо міграція видаляє чи змінює дані — зупинись і нагадай користувачу зробити `mysqldump` поза репозиторієм,
   потім прогін на копії: `DB_NAME=<копія> npm run migrate`. Без підтвердження користувача на реальній БД не запускай.
6. Для безпечної (не руйнівної) міграції: `npm run migrate`, потім `npm run test:api`.
7. Якщо змінилась схема, на яку спирається код (`services/`, `routes/`), онови його й додай тест у `server/tests/`.
8. Не коміть, доки користувач не попросить.
